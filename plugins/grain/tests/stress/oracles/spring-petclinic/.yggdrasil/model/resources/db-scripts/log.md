The schema is written by hand, one file per supported database, and the application is configured never to generate or alter it. That is the opposite of the usual default and it is deliberate: this codebase is read as a reference, and a schema that only exists as a side effect of the object mapping cannot be read. The cost is that the same database has to be described three times, in three dialects, and the three descriptions can drift - which has happened, when a uniqueness guarantee expressed in one dialect's syntax did not mean the same thing in another. Uniqueness of a pet's name within one owner belongs here rather than only in application code, because two simultaneous requests both pass an application check and only a constraint stops both of them saving.
