Form binding here writes into persistent objects directly, with no intermediate data-transfer object, which is what keeps these screens short. The safety that decision costs is bought back explicitly: every binder in this area refuses to bind an identifier, at the top level and at any nested path, so a crafted request cannot re-point a save at somebody else's row. Both halves of that refusal are needed - an earlier version blocked only the top-level identifier and left the nested one reachable through the owner form, which binds a whole unit at once. Duplicate pet names are rejected in two places on purpose: here so the user sees a field error, and in the database so two simultaneous requests cannot both pass the check and both save.
