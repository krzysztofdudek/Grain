
## 2026-09-02 00:27 — Fixed: history.mjs's monolithic JSON.stringify(state)/JSON.parse(readFileSync) round-trip (the ONLY swallow-adjacent code, not an unrelated catch) replaced with a streaming NDJSON writer/reader (writeHistoryState/readHistoryState) — every JSON.stringify call is now bounded to one record (scalar field, map entry, or fps row), never the whole state, so it can never hit V8's string-length cap regardless of repo size. Both the read and save steps are now wrapped in try/catch that logs a clear [history]-prefixed diagnostic via the existing log() callback instead of failing silently (read: 'saved history state unreadable (...) — walking full history instead of resuming'; save: 'could not save history state (...) — this run's results are unaffected, but the next run will re-walk'); a save failure no longer discards the already-computed in-memory result. Also fixed grain.mjs's how-hook, the one other direct consumer of history.json's raw format, to read it via the new readHistoryState instead of generic JSON.parse (it would otherwise have gone permanently silent on every repo, not just huge ones). Updated 5 existing tests that read/wrote history.json directly to use the new (de)serializer; added tests/history-large-state.test.mjs (3 tests) proving (1) no JSON.stringify call exceeds one record even at 350k+ synthetic entries, with lossless round-trip, (2) a corrupt/legacy-format save is a loud diagnostic + full re-walk, not a crash, (3) a write failure (ENOENT on the destination dir) still returns the fully-computed H, loudly.
